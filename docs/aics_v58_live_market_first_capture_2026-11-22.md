# AICS V58 — первый реальный автоматический захват S&P 500 для prospective learner

**Дата первого фактического исполнения:** 22.11.2026, 13:21 UTC. **Статус:** production source *collector*, но **не** production market forecasting model, не сертифицированная историческая PIT, не полный AICS. **Первый успешный CI:** [GitHub Actions #45027020151](https://github.com/nikitamalinovskiybcs-beep/Fly/actions/runs/45027020151), **9/9 тестов**.

## Что теперь действительно собирается, а не симулируется

Автономный модуль [`scripts/aics_v58_first_capture_sp500.py`](../scripts/aics_v58_first_capture_sp500.py) скачал **реальный исходный ответ** FRED по ряду S&P 500 `SP500` с `https://fred.stlouisfed.org/graph/fredgraph.csv?id=SP500`. GitHub Actions содержит следующий фактически зарегистрированный receipt:

| Первичная техническая метрика | Реальный результат |
|---|---|
| Момент завершения получения исходного CSV | `2026-11-22T13:21:12.403535+00:00` |
| SHA256 исходных байтов CSV | `956d4a10a289d499f89029d6f7fb72cf5d48ca709c414e71a52f0a2076f82242` |
| Получено байтов | 48 922 |
| Число исходных дневных строк с настоящим числовым закрытием | **2513** |
| Пропуски/пустые дневные значения в исходном CSV | 96 |
| Последний предшествующий календарный месяц по фактическому времени запуска | Октябрь 2026 |
| Можно считать октябрь новым prospective прогнозом после регистрации 22.11? | **Нет** |
| Добавлено записей в prospective V56 ledger | **0** |
| Фактических новых V55-прогнозов / созревших исходов / обновлений V56-весов | **0 / 0 / 0** |
| Весь 11-узловой индекс AICS | `null` |

В отличие от предыдущих численных V50–V57 экспериментов, это **действительно был отдельный сетевой запрос к внешнему источнику внутри CI**, а не повторный расчёт загруженных заранее файлов. Исходный FRED CSV скачан в временную файловую систему GitHub runner, **не добавлен в репозиторий или распространяемый Actions-артефакт**, потому что данные S&P Dow Jones Indices, отображаемые в FRED, защищены авторским правом. В Actions-артефакте — только метаданные захвата, проверочная сумма и, когда станет доступен, единичное месячное значение. **Байты источника не были внешне независимо архивированы** и эта работа **не** доказывает provider-first-delivery PIT.

## Как теперь работает следующий реальный месяц

[GitHub Actions V58](../.github/workflows/aics-v58-fred-source-first-capture.yml) запланирован **каждый рабочий день в 23:45 UTC**. Алгоритм:
1. Скачивает оригинальный FRED CSV. При HTTP 403/429, тайм-ауте, неожиданной форме CSV, нечисловой цене, неверной хронологии **останавливается**; не подставляет старое значение и не генерирует цену.
2. Фиксирует момент реального HTTP-получения, сумму SHA256 всех исходных байтов и фактические числовые дневные строки. **Никаких provider timestamp не выдумывается**: `retrieved_at_utc` — наше наблюдение, не время публикации ФРБ и не первичная публикация S&P.
3. Берёт **только предыдущий календарный месяц**, исключительно начиная с **ноября 2026**, и только если **в том же исходном ответе есть хотя бы одно реальное дневное закрытие следующего месяца**. Это необходимая проверка завершённого месячного ряда. Без декабрьской реальной котировки значение за ноябрь отсутствует, даже если местный календарь уже декабрь.
4. Сверяет receipt **с заново разобранными теми же исходными CSV-байтами** перед добавлением. Запись в V56-журнал строго append-only. Если значение того же месяца изменилось в новом источнике, процесс **останавливается** и не переписывает исходную «first captured» запись.
5. Если впервые появился допустимый месяц, GitHub Actions автоматически сохраняет **одну числовую месячную запись** с source-URL, SHA256 и `retrieved_at_utc` в существующий [журнал V56](../aics_data/research/aics_v56_prospective_forecast_outcome_ledger.json). Не меняет формулы пяти экспертов или основной AICS.
6. Добавленная запись в журнале запускает уже реализованный [V56 weekly learner](../.github/workflows/aics-v56-feedback-learner.yml), но **сам по себе будущий S&P close не создаёт новый прогноз**: отдельно требуются все 11 реально засвидетельствованных признаков `B,S,BM2,SM3,BM3,SM2,loss3,loss1,vol,accelB,accelS`, указанных в frozen V55.

### Что точно не достигнуто

- Пока **нет первого завершённого prospective ноября 2026** (и тем более первого future outcome), нет права объявлять прогноз или обучения весов.
- Получение опубликованного FRED CSV — **не независимая провайдерская PIT-сертификация** и не юридическое подтверждение права на распространение полного исторического source dataset.
- Автоматически собирается **только один тип данных**: дневной `SP500`, который преобразуется в единственный следующий допустимый месячный close. Автоматического получения исходных Private Credit, Insurers, Semiconductors и всех **11 текущих feature-определений** пока нет. Это следующий инженерный блокер.
- Модель не перенастраивается «бесконечно»: любые повторные запросы в один и тот же месяц идемпотентны. Без новых исходов не будет новых обучающих примеров и не может возникнуть доказанная высокая точность.
- Аудит проекта не пересчитывается: **22/66**, **0/11** независимых PIT-сертифицированных узлов, официальный `AICS=null`, никаких сделок.

## Следующее содержательное улучшение

Реализовать столь же строгую **первичную регистрацию 11 входных признаков shadow-ансамбля**. Данные должны поступать из настоящих оригинальных отчётов/прайс-фидов с `source_first_seen_at_utc` и реальным контролем SHA256. Только когда все 11 доступны на одной дате после первой публикации, V55 может сделать настоящий сохраняемый прогноз, а V56 — позднее учиться на истинной будущей ошибке.

**Источники:** [FRED SP500](https://fred.stlouisfed.org/series/SP500) и [FRED graph CSV](https://fred.stlouisfed.org/graph/fredgraph.csv?id=SP500); первый рабочий запуск GitHub #45027020151. Подтверждение пределов авторских прав и временной семантики есть на странице FRED.
