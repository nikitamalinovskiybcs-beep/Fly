# Порядок закрытия 66 этапов AICS

66 ячеек образуются из 11 узлов и 6 последовательных решений. Один исходный документ хранится по одной ссылке. Один обзор может охватить несколько узлов. По каждому узлу проверяющий указывает вывод и ссылку на основание. При повторном использовании файла сохраняются его неизменяемая версия и SHA-256.

| Этап | Общая работа | Что требуется по каждому узлу |
|---|---|---|
| 1. Реестр | Единый перечень источников | Зафиксированные состав и источники |
| 2. Архив | Однократное получение и проверка файла | Привязка узла к оригиналу |
| 3. Историческая доступность | Общая сверка источников и дат | Подтверждённые состав, значения и доступность входов на исторические даты |
| 4. Методика | Одна версия правил и один независимый обзор | Проверенная формула 0–100, единицы, пропуски и применимость показателей |
| 5. Вневыборочная проверка | Один заранее зафиксированный протокол и запуск на общей временной оси | Отложенные 24 месяца, неизменённая версия модели и результат по узлу |
| 6. Сертификация | Один независимый итоговый отчёт | Явное решение по каждому узлу с пройденными этапами 1–5 |

## Как регистрировать общий независимый обзор

В существующий массив соответствующего этапа в independent_audit добавляется одна запись с evidence_path и evidence_sha256. Одиночные записи с полем node продолжают работать. Общий JSON-документ содержит schema_version со значением aics-shared-review-v1, audit_field с названием массива и объект decisions. Ключи decisions — точные имена узлов. У каждого решения есть outcome (passed или open) и basis со ссылкой на раздел доказательств. Содержание обзора должно идентифицировать независимого проверяющего, охват данных, метод проверки и её результат. До регистрации ответственный сверяет эти основания. Формальная проверка файла не удостоверяет полномочия автора.

## Какие доказательства ещё нужны

- UST 30Y и Repo. Повторное сравнение 48 месячных выгрузок уже выполнено. Для дат отсечения нужны архивные выпуски H.15 и публикации ставок Нью-Йоркского ФРБ с датами выхода. Для Repo отдельно проверяется охват выбранных входов.
- Private Credit, Insurers, Neoclouds, Hyperscalers, SPV, Semiconductors Supply и AI Demand. Обработать общий список SEC accession один раз. Сопоставить раскрытие с историческим реестром публикаций, применить задержку 14 календарных дней. По узлам отдельно проверить состав эмитентов и пригодность полей. Для Insurers нужны также применимые регуляторные источники, для Semiconductors Supply — винтажи G.17, для AI Demand — отдельно раскрытый спрос на ИИ.
- Power/Data Centers. Использовать общий архив макровинтажей для доступных серий. Проверить дату выхода и относимость к дата-центрам для выбранных данных EIA и корпоративных раскрытий.
- AI Equities. Нужны исторический состав корзины, доступные на каждую дату корпоративные события и разрешённые ценовые ряды.

Источником счётчика служит aics_data/progress/status.json. Повторная загрузка, сверка хеша и успешный запуск CI сами по себе этапов не добавляют.
